## 2. 已确认的产品约定

### 产品形态与启动方式

- 面向公开用户提供 Windows x64 管理软件，采用 Python + PySide6；首次目标为 Antigravity 2.28.2，不据此承诺其他版本可用。
- 使用 PyInstaller 构建并通过 Inno Setup 分发 Windows 安装程序，随包提供运行依赖及连接测试所需 Node，普通用户无需安装 Python／Node。
- 首次打开管理器，选择安装目录、核对兼容状态、配置 API、主动测试连接，再启用翻译组件；安装切换前提示用户保存工作并退出目标应用。
- 配置完成后可以关闭管理器。用户直接启动 Antigravity 或从管理器点击启动；检测、翻译及候选缓存运行在 Antigravity 内，无需管理器常驻。
- 通过管理器查看和修改词典、审核候选、维护翻译组件及代理启动入口；不增加开机常驻或独立清理服务。
- API 默认关闭，连接测试只在用户主动操作时运行。配置保存、API 测试、版本兼容、组件安装和运行连接分别显示状态。

| --- | --- |
| 概览 | 选择安装、查看版本／兼容／运行状态、应用汉化、还原、启动 |
| 词典管理 | 搜索默认和个人词条、个人覆盖、恢复默认、JSON 导入导出 |
| 待确认译文 | 显示原文、译文、剩余期限；采纳、编辑后采纳、拒绝、管理拒绝记录 |

仅检测经过版本验证的软件界面文案；聊天正文、用户输入、代码／编辑器、终端、执行日志和内嵌网页不进入翻译管线。原生菜单首版保留现有静态汉化，不接个人词典热更新或 AI。默认词典精确数据可视化管理，正则及识别逻辑继续由代码维护。

首版保留现有 OpenAI Responses、Gemini generateContent、Claude Messages、OpenAI-compatible Chat Completions 四种适配器及公网 HTTPS 地址范围，不扩展本地模型或任意自定义认证协议。

### 词典与候选生命周期

目标优先级为：**个人词典 → 内置词典／规则 → 有效待确认译文 → AI**。个人词典包括手工条目及用户已采纳的 AI 译文；修改默认译文保存为个人覆盖，不修改随包内置数据。删除覆盖可恢复默认，内置词典更新不覆盖个人修改。

| 事件 | 行为 |
| --- | --- |
| AI 返回有效译文 | 临时显示并写入独立候选目录，不直接写入正式词典 |
| 再次遇到相同候选 | 仅在未过期时复用；跨启动有效，不延长原保留期 |
| 采纳／编辑后采纳 | 在锁内核对版本和有效期，保存正式词条，再移除候选 |
| 主动拒绝 | 移除候选，恢复默认译文或英文；保存独立拒绝记录，阻止自动再次请求 |
| 解除拒绝 | 允许后续按正常未命中流程请求；解除操作本身不自动联网 |
| 到期 | 删除未采纳候选并使旧显示／响应失效；再次遇到该文案时允许新请求 |

候选保存到用户目录下独立的 `pending-translations/`。从首次成功生成起默认保留 **7 × 24 小时**，复用不续期；正式词典和拒绝记录不受候选清理影响。管理器或翻译组件启动时及运行期间定期清理，每次展示、复用、采纳仍即时核对有效期。两个软件都退出时不进行后台清理，下次启动再执行。

清理本身不调用 AI；当前仍可见且满足白名单的文案可以作为新的未命中处理。并发去重不得刷新已有候选的生成时间；过期、拒绝或人工修改后，在途旧响应不能恢复旧候选或覆盖正式词条。候选持久化失败应显示明确状态，不误报已保存。

### 用户数据及兼容迁移

- 继续使用 `%APPDATA%\Antigravity-zh-CN`，与管理器及 Antigravity 安装目录分离；保留跨进程锁、版本号和原子保存。
- 旧手工词条保留；以前自动保存的 AI 词条保留在正式词典并标记为“历史已保存，未人工审核”，不搬入 7 天目录后自动删除。
- 旧 `autoSave` 行为迁移为待确认流程。Python 和 Node 同步升级数据协议，迁移应可恢复；旧运行时遇到不支持的新格式时暂停增强翻译并提示更新组件，不覆盖数据。
- 公开版本使用 Windows 当前用户绑定的凭据保护（DPAPI），密钥不进入页面、日志、命令行参数或词典导出。当前明文配置的迁移属于后续工作，M0 不读取真实密钥。
- 重新汉化、还原、升级保留用户数据；卸载提供明确的翻译还原和代理入口移除流程，恢复失败时保留所需组件并报告原因。首版采用完整安装包升级，不增加自动更新服务。

## 4. 目标架构与接口边界

```text
PySide6 管理器
  ├─ 配置／词典／候选审核 ── 用户数据目录（版本、锁、原子保存）
  └─ 安装／还原／代理服务 ── 检测 → 操作预览 → 执行 → 结构化结果

Antigravity 内的翻译组件（管理器关闭后仍运行）
  受审核 UI 节点 → 统一词典管线 → 受限 IPC → 主进程翻译服务
                                             ├─ 用户数据／候选
                                             └─ provider／网络层 → 用户配置的 API
```

- GUI 与原 CLI 调用同一服务层，返回目标安装、操作清单、逐项状态、错误码、是否需重启等结构化结果，不解析中文日志判断成功。M0 不新增或变更实际 API。
- 耗时检查、安装和网络操作不阻塞 GUI；文件操作成功与启动成功分别呈现。凭据、存储及网络错误应明确报告，不能阻止原应用正常启动。
- 网络调用由主进程执行，不暴露通用 IPC、任意文件读写或密钥给页面。复用异步队列、去重、限流、超时、取消和旧结果失效机制。
- 内置字典抽离、个人覆盖和原文恢复必须一并处理，不能只交换查词顺序。新增候选版本参与 snapshot 和旧响应检查；新 schema 及接口细节在对应阶段记录中固化。
- 当前 profile 使用精确 URL，2.28.2 的界面使用本地动态端口；适配应绑定目标窗口和应用实际服务地址、验证界面来源，并处理导航／服务重启后的撤销与重新绑定。不能放行所有 loopback 页面或降低 sandbox/contextIsolation 来绕过检查。
- 安装修改保持暂存、校验、切换、失败回滚；保留 `app.asar.disabled` 等恢复来源。M1 使用隔离测试安装，不直接对用户日常安装试错。
- 代理页面按扫描、预览、执行、逐项结果组织。保留精确路径匹配、并发修改检查、先恢复快捷方式再删除启动器等约束；不修改全局系统代理或执行策略。
- 系统代理识别、端口 TCP 连通、API 测试分别报告。代理入口只影响新启动的进程；API 网络层不依赖先配置快捷方式。

## 6. 当前使用、已知限制与恢复方式

