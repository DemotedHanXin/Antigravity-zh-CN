# 在 feat/DragonGirl 上分阶段开发与审核

本文保存 2026-11-02 制定的原始方案，下文的起点提交和“本轮”均指规划时状态；当前实施与审核状态以 [开发进度](development/PROGRESS.md) 为准。
## 1. 固定开发规则

制定计划时，分支为 `feat/DragonGirl`，提交为 `559020e`，工作区干净。后续全部开发在该分支完成。

- 不合入 `main`，不新建功能分支，不删除现有分支。
- 每次只实施一个阶段。
- 阶段完成后，更新记录文档、完成验证、创建 Git commit 和附注标签。
- 交付阶段成果后停止，等待你明确审核通过，才开始下一阶段。
- 你提出修改意见时，只修订当前阶段，修完再次交审。
- 默认只创建本地提交和标签；推送远端、合并和发布另行安排。

原始规划轮只更新方案，不执行代码修改、提交或打标签；后续已按阶段实施。

## 2. 保持已确认的产品方案

开发 Python + PySide6 Windows 管理器，提供安装程序及完整运行依赖。首次配置并安装翻译组件后，用户可以关闭管理器，直接使用 Antigravity。

首个适配目标为你提供的 **Antigravity 2.28.2 / Windows x64**。

管理器包含概览、词典管理、待确认译文、AI 设置、代理与启动、日志诊断。翻译仅覆盖经过验证的软件界面文案，排除聊天正文、代码、输入内容、终端和内嵌网页；原生菜单暂沿用静态汉化。

翻译顺序固定为：

```text
个人词典 → 内置词典／规则 → 有效待确认译文 → AI
```

待确认译文独立保存，从首次生成起保留 7 天，复用不续期；采纳后进入正式词典。过期清理后允许重新翻译，主动拒绝则保持抑制，直到用户解除。清理在管理器或翻译组件运行时进行，不增加常驻清理服务。

## 3. 阶段安排与完成条件

| 阶段 | 工作内容 | 交审条件 |
|---|---|---|
| **M0：基线与开发约定** | 固化需求、架构、阶段边界和验证基线，建立进度及阶段文档 | 文档能明确说明已有能力、缺口、目标版本和后续步骤 |
| **M1：真实版本接入** | 在隔离测试安装中验证 2.28.2 的窗口、preload、本地动态端口和界面区域，建立兼容配置 | 跑通未命中文案的请求、显示与还原；管理器关闭后仍能工作；非允许区域不采集 |
| **M2：词典与审核流程** | 抽离内置词典、统一 DOM 翻译管线，实现个人覆盖、候选目录、7 天清理、采纳／拒绝和数据迁移 | 覆盖优先级、即时更新、到期和并发行为正确，旧词典不丢失 |
| **M3：统一管理器** | 完成 PySide6 界面、共享服务接口、状态显示、后台任务和密钥保护 | 用户能通过界面完成配置、词典编辑、译文审核及汉化／还原操作 |
| **M4：代理与 Windows 安装包** | 接入代理扫描、预览、启用／移除，完成 PyInstaller 构建和 Inno Setup 安装程序 | 无 Python／Node 的干净环境可安装使用，升级保留数据，卸载及恢复流程可验证 |
| **M5：发布前验收** | 完整回归、真实应用验收、更新使用与维护文档、准备测试版产物 | 提交可审核的候选安装包、支持矩阵和验证记录；等待你批准发布 |

各阶段严格顺序推进。M0 审核通过前不开始 M1，以此类推。

实现中继续保留以下约束：

- GUI 与 CLI 共用结构化服务接口，不通过解析控制台中文输出判断结果。
- 安装操作沿用暂存、校验、切换与失败回滚。
- 适配动态端口时绑定目标应用窗口与实际服务，不能放行所有本机页面。
- API 保留现有四类协议及异步去重、限流、超时处理；密钥采用 Windows 用户绑定保护，不进入页面、日志或词典导出。
- 代理配置成功、端口连通、API 可用分别报告。
- 旧手工词条及历史已保存 AI 词条保留，后续 AI 结果统一进入待确认流程。

## 4. 每阶段的文档、提交和标签

建立两类记录：

- `docs/development/PROGRESS.md`：总进度、当前阶段、审核状态、对应提交／标签和下一步。
- `docs/development/M0-baseline.md` 等阶段文档：每阶段独立一份。

每份阶段文档固定记录：

1. 阶段目标及实际完成内容。
2. 主要实现、接口或数据格式变化。
3. 验证命令、结果、跳过项和未验证范围。
4. 使用方式、已知问题及恢复方法。
5. 需要你审核的内容。
6. 下一阶段待办及进入条件。

首次交审使用一个阶段提交和附注标签，例如：

```text
提交：docs: complete M0 baseline and development agreement
标签：manager-v0.1.0-m0-review.1
```

审核返工产生新提交和新标签，例如 `manager-v0.1.0-m0-review.2`，不移动或覆盖旧标签。

标签表示“可供审核的阶段快照”，不表示你已批准，也不表示正式发布。文档用标签名称定位快照；提交后在交付消息中报告实际 commit SHA，避免文档引用自身提交哈希的问题。

## 5. 验证与审核停点

各阶段运行与改动相关的测试，不把模拟测试通过当作真实应用验收完成。重点覆盖：

- 关闭 AI 后零新请求，管理器关闭后翻译组件仍正常运行。
- 人工覆盖、恢复默认、旧响应失效与并发写入保护。
- 7 天边界、休眠恢复、过期采纳、拒绝时仍有请求在途。
- 汉化、重复汉化、还原、代理启用／移除及失败恢复。
- 安装包在干净 Windows 环境中的安装、升级和卸载。

每次交审提供：**完成内容、文档位置、验证结果、commit SHA、标签、审核步骤和下一阶段待办**。

交审后不提前实施下一阶段；只有收到你明确的“审核通过，继续下一阶段”等指示，才进入下一阶段。下一次开始实施时，先完成 **M0**。
